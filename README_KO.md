# 대운교통 SafeDrive AI v1.4.1

## 1. 시스템 목적

SafeDrive AI는 **버스기사별 실제 운행기록을 분석하여 개인별 운전습관을 확인하고 기사 본인에게 피드백**하기 위한 시스템입니다.

```text
기사 근무배차 + 일일 노선·운행순위
            + 노선별 전체 운행시간표
            + TAGO/BIS 실제 운행차량
                         ↓
             기사별 실제 운행차량 확정
                         ↓
             실제 차량 CDT/TACO 분석
                         ↓
         기사별 일·월 운전습관 및 코칭
```

- **배차표**: 어느 기사가 어느 예정차량을 운전하는지 확인
- **일일 노선·운행순위 자료**: 해당 차량의 당일 노선·순번·AM/PM 예정출발 확인
- **노선별 운행시간표**: 전체 노선·운행순위의 기준 운행시간. 새 파일을 다시 올리기 전까지 계속 적용
- **BIS/TAGO**: 배차차량과 실제 운행차량이 같은지 실시간 확인
- **CDT/TACO**: 확정된 실제차량의 속도·브레이크·GPS 등의 운행기록 분석

CDT는 차량변경의 원인을 판정하는 자료가 아닙니다. **차량변경은 BIS로 판단하고, CDT는 확정된 실제차량을 기사 분석에 연결하는 자료**입니다.

## 2. v1.4.1 핵심 수정

- 첨부 `20261104_report.csv`의 실제 헤더 **`운행순번`** 인식 오류 수정
- CP949/EUC-KR CSV 자동 판별
- 일일배차 `.csv/.xls/.xlsx` 개별·다중 동시 업로드
- 기사 근무배차와 일일 노선·순번을 업로드 순서와 관계없이 자동 병합
- 시간표는 다음 업로드 전까지 계속 적용, 새 버전 업로드 시 이전 버전 종료일 자동 정리
- 별도 휴일/특수운행일 수기 입력 UI 제거
- 일일배차 예정출발을 BIS 활성회차 판정의 우선 기준으로 사용
- BIS 확정 실제차량을 CDT 기사매칭에서 예정차량보다 우선 적용
- CDT 지정폴더 **하위폴더 전체 재귀검색**
- Collector State와 Supabase의 CDT 처리이력이 불일치하면 선택적 자동 재처리
- 수집현황에 전체 CDT/DB확인/신규후보/이번처리/대기건수 표시

## 3. 기존 환경을 보존한 갱신

### 반드시 백업

기존 운영 폴더에서 아래 3개 파일을 별도 보관합니다.

```text
웹 루트\config.js
collector\collector_config.json
collector\collector_state.json
```

이 3개 파일에는 운영환경 또는 처리이력이 있으므로 **새 ZIP의 파일로 초기화하지 않습니다.**

### Supabase

기존 v1.3.0을 운영 중이면 SQL Editor에서 다음 파일만 **1회 실행**합니다.

```text
sql\08_v1_4_1_safe_update.sql
```

이 SQL은 기존 기사, 배차, 시간표, BIS, CDT 분석 데이터를 삭제하지 않습니다.

### GitHub / Netlify

기존 저장소에서 다음 파일·폴더만 교체합니다.

```text
index.html
assets\
netlify.toml
```

기존 `config.js`는 그대로 유지합니다.

GitHub Desktop에서 Commit → Push 후 Netlify Published를 확인하고 브라우저에서 `Ctrl+F5`를 수행합니다.

### Collector

새 `collector` 폴더로 프로그램 파일을 교체하되, 백업한 아래 파일을 다시 복사합니다.

```text
collector_config.json
collector_state.json
```

`SafeDrive_Collector_Control.bat`를 실행해 자동실행을 재설치하고 수집을 재시작합니다.

## 4. 배차 업로드 방식

관리자 `일일 배차표`에서 다음 파일들을 **각각 올려도 되고 동시에 여러 개 선택해도 됩니다.**

1. 기사 근무배차 파일
   - 차량번호
   - 운전자이름
   - 근무시작/종료 일시

2. 일일 노선·운행순위 파일
   - 일자
   - 노선번호
   - 운행순번
   - 오전출발시간
   - 오후출발시간
   - 차량번호

시스템은 `운행일 + 차량번호 + AM/PM`으로 두 자료를 병합합니다.

첨부 샘플 기준으로:

- 기사 근무배차: 254건
- 일일 노선·운행순위 CSV: 127행 → AM/PM 254건
- 두 자료의 차량·AM/PM 매칭: **254/254건** 확인

## 5. 노선별 운행시간표

시간표 Excel에는 평일/토요일/일·공휴일을 포함한 전체 노선·운행순위의 운행시간이 들어 있습니다.

- 최초 등록 후 다음 시간표 업로드 전까지 계속 적용
- 새 시간표 업로드 시 이전 버전은 새 적용일 전날까지 자동 종료
- 별도 휴일 입력은 요구하지 않음
- BIS 당일 비교는 일일배차의 노선·순번·예정출발을 우선 사용
- 시간표는 기준운행시간 확인 및 일일자료 보완에 사용

## 6. BIS 실제 운행차량

Collector는 운행 중 다음 흐름으로 비교합니다.

```text
일일배차 예정차량
  + 노선번호 / 운행순번 / 예정출발
          ↓
TAGO/BIS 해당 노선 실시간 차량
          ↓
예정차량과 실제차량 비교
          ↓
반복 불일치 확인
          ↓
출발대체 또는 운행중교체 저장
```

배차표와 다른 차량은 관리자 `실제 운행차량` 메뉴에서 기사·노선·순번·예정차량·실제차량 기준으로 확인합니다.

BIS 전체 위치 스트림은 Supabase에 저장하지 않고, **확정된 실제차량 연결/차량변경 이력만 저장**합니다.

## 7. CDT/TACO 수집

기본 폴더:

```text
E:\Choyoung\ADTviewer\Data
```

v1.4.1은 위 폴더와 **모든 하위폴더의 `.CDT` 파일을 검색**합니다.

CDT는 차량 입고·수리로 며칠 늦게 수집될 수 있으므로 수집일이 아니라 파일의 실제 운행일을 기준으로 과거 배차와 BIS 실제차량 이력에 재연결합니다.

### 수집현황 표시

- 폴더 내 CDT
- Supabase에서 확인된 기존 처리 파일
- 신규/재처리 후보
- 이번 Collector 실행 후 처리 파일
- 기사매칭 대기 파일

Collector의 로컬 상태에는 처리완료로 되어 있지만 Supabase에 해당 파일 결과가 없으면 해당 파일만 자동 재처리합니다. `collector_state.json` 전체 삭제는 필요하지 않습니다.

## 8. 기사별 분석

매칭 우선순위:

1. BIS로 확정된 실제차량
2. 차량변경이 없는 경우 배차 예정차량

따라서 예를 들어 배차차량이 `1172`이나 실제 BIS 차량이 `1188`이면 **1188의 CDT가 해당 기사 분석에 사용**됩니다.

분석은 2026-10-01부터 일·월 단위로 관리합니다.

- 운행거리
- 최고속도
- 급출발 후보
- 급가속 후보
- 급감속 후보
- 급정지 후보
- 관리속도 초과 후보
- 100km당 위험이벤트
- 전월 대비 변화
- 기사 확인여부

SafeDrive 결과는 회사 내부 안전교육·코칭용 참고자료이며 교통안전공단 공식점수 또는 법규위반 확정자료가 아닙니다.

## 9. 저장용량 정책

Supabase에는 다음 최소정보만 저장합니다.

- 기사·차량·노선·순번 배차
- 시간표 버전/슬롯
- BIS 실제차량 연결·차량변경 이벤트
- CDT 파일명·해시·운행일·레코드 수 등 메타정보
- 기사별 일/월 집계
- 유형별 대표 이벤트 소수
- 기사 확인 및 Collector 상태

Supabase에 저장하지 않습니다.

- CDT 원본
- CDT 1초 전체 레코드
- BIS 전체 위치 스트림
- 원본 Excel/CSV
- API key/비밀번호

## 10. 운영 확인순서

1. `일일 배차표` → 기사·차량·노선·순번 확인
2. `노선 운행시간표` → 최근 적용 버전 확인
3. `수집현황` → CDT 파일수·BIS 활성노선 확인
4. `데이터 연계` → 배차 → 시간표 → BIS → CDT → 기사분석 단계 확인
5. `실제 운행차량` → 배차와 다른 차량 확인
6. `기사 운행분석` → 일·월 안전운전 결과 확인
