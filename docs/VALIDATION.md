# v2.0.0-rc1 검증 및 한계

## 기반과 범위
사용자가 첨부한 v1.4.2 Fleet Update(1).zip의 app.js/index.html/fleet.js와 기존 safedriver 소스를 기반으로 만든 추가 업데이트다. config.js, collector_config.json, 기존 DB 자료를 패키지에 포함하지 않는다. 운영 서버를 변경하거나 외부 메시지를 발송하지 않았다.

## 로컬 검증
- PGlite: 기존 01_schema.sql 기반 + 새 SQL 11 두 차례 적용. 비밀번호 해시 관련 pgcrypto 함수만 테스트용 대체 함수를 사용했으므로 암호화 자체의 테스트는 아니다.
- DB 검증: 세션/역할 확인, 초기 비밀번호 변경 강제, 기사 간 접근 차단, 미게시 자료 차단, PDF·엑셀 완비 조건, 변경 리비전 충돌, 확인 상태 초기화, 내부 메모 차단, 계정 비활성화, 원본 보고서 보존, 직접 익명 호출 차단.
- Python 7개 테스트: 연도 경계/기간 검증, 계획 중복/보류 상태 유지, 위험 파일명 거절, B 표식·월 대조, 원자적 저장/중복/충돌, 디스크 쓰기 실패, 명부 중복.
- Netlify gateway mock: 허용 동작 목록, 서명 전에 권한 확인, 잘못된 파일 서명 거절, 업로드 순서와 커밋, 다운로드 URL 생성.
- Chromium UI mock: 관리자 검증·게시, 계정 입력창, 파일명 계정 연결, 피드백 폼, 기사 전용 버튼 제한, 390px 화면.
- 기존 index.html/app.js 전체를 사용한 mock 브라우저 통합: 기존 로그인, 메뉴 전환, 설정, 새 수집 화면 통과.
- Python 컴파일, JS 구문 검사 통과.

## 아직 검증하지 않은 항목
- eTAS 실사이트 자동 조회/페이지 이동/팝업/저장/다운로드. 실제 DOM을 제공받지 못했으며 화면을 토대로 범용 탐색과 클릭 지정 도우미를 작성했다. 자동화 호환성을 보장하지 않는다.
- Windows Tk UI, 전용 브라우저, Google Drive G: 실제 쓰기/동기화.
- 실제 Supabase Storage SQL 12, Netlify 환경변수와 함수 배포, 파일 서명/전송 통합, 운영 DB 마이그레이션.
- 실제 공단 PDF 및 XLSX의 텍스트 추출 성공률. 명확히 확인할 수 없는 파일은 관리자 확인 대상으로 남긴다.

## 의도된 제한
- 파일당 웹 등록 최대 3MB. 파일 서명/확장자 검사는 전체 문서의 무결성이나 내용 검증과 같지 않다. 관리자 대조 필요.
- PC 수집기는 연결 오류 한 건 발생 시 다음 대상 진행을 멈춘다. 수백 건의 반복 실패 방지 목적. 관리자가 확인 후 선택 재수집한다.
- 화면 연결 도우미에서 선택한 CSS 경로는 사이트 개편 시 다시 지정해야 한다. 탐색 가능한 페이지 번호만 처리하며 숨겨진 페이지 그룹은 추가 사이트 연결 수정이 필요할 수 있다.
- PC 큐는 해당 Windows 사용자 로컬에 저장된다. 여러 PC 간 자동 동기화·분산수집은 지원하지 않는다. 한 PC에서 한 수집기만 실행한다.
- 계정 삭제는 active=false와 세션 종료 방식으로 구현. 역사 자료와 계정 행을 물리 삭제하지 않는다.
- 열람 기록은 PDF 열기 요청이며 내용 이해·실제 완독 확인이 아니다.
- 파일 링크는 60초 유효한 bearer URL이다. 만료 전 링크를 가진 사람은 접근 가능하므로 절대적인 재공유 차단 수단은 아니다. 권한 검사 후에만 발급한다.
- 웹 게시 상태는 자료 교체 시 해제된다. 이전 원본을 자동 삭제하지 않으므로 추후 보관 정책과 정리 절차 필요.
- 인사 상태의 현재값·적용일 및 변경 감사로그를 남긴다. 복잡한 다중 휴직 기간 계산은 구현하지 않았다.
- 문자 발송 제외. 분기·반기·연간 수치 계산/대시보드는 추후 실제 엑셀 지표 정의 후 개발. 이번 버전은 PDF·엑셀 원본과 기사·월 연결을 보관한다.
- 기존 배차표·시간표 유지. BIS/CDT 메뉴는 제외했지만 이미 실행 중인 Windows 구수집기는 자동으로 중지되지 않으므로 운영 전환 후 직접 중단·자동실행 해제해야 한다.
