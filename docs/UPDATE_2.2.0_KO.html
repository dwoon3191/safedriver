SafeDrive v2.2.0 업데이트 안내

v2.0.0-rc1 위에 덮어쓰는 업데이트이며 v2.1.0 내용을 모두 포함합니다. 2026-11-19 작성.

먼저 확인하세요.
이 업데이트는 운영 사이트와 데이터베이스에 자동 적용되지 않습니다. 이 ZIP을 만든 환경에서는 실제 Supabase 프로젝트, 실제 휴대폰, Netlify에서 실행해 보지 못했습니다. 아래 "시험 확인표"를 시험용 기사 계정으로 먼저 확인한 뒤 기사님들께 알려 주세요. config.js, app.css, 이미지, netlify.toml은 이 ZIP에 없으며 바꾸지 않습니다.

무엇이 바뀌나요

구분변경
배차 관리 (관리자)새 메뉴 배차 관리. 배차시간표 CSV와 승무원표 XLS를 3~4일치 함께 선택해 올리면 노선·운행순번으로 합치고 검사합니다. 날짜별 배차일지 표(차량·노선·순번·오전반·오후반·출발시각), 오전반·오후반 인원, 휴무자 목록을 볼 수 있습니다.
오늘 근무 (기사)기사 로그인 첫 화면이 오늘 근무입니다. 본인의 오전반/오후반, 노선, 배차순번, 차량, 출발시각을 큰 글씨로 보여 줍니다. 오늘·내일·모레 버튼, 휴무는 "휴무"로, 파일이 아직 없는 날은 "배차 미등록"으로 표시합니다. 같은 차의 반대 시간대 기사와 같은 노선 전체 기사는 눌러서 펼쳐 봅니다.
PDF를 앱 안에서 보기리포트 보기를 누르면 별도 PDF 앱 없이 앱 화면 안에 표시합니다(무료 오픈소스 pdf.js, 확대/축소 버튼). 어떤 이유로든 실패하면 기존처럼 링크로 열립니다. 열리면 열람·확인이 자동 기록됩니다.
로그인 접속접속 정보가 없는 기기에서는 URL·키 입력 칸 대신 "관리자에게 문의해 주세요"만 보입니다. 관리자가 새 기기에서 설정해야 하면 주소 끝에 #admin-setup을 붙입니다.
옛 BIS/CDT 메뉴관리자 메뉴에서 "기존 배차표", "기존 시간표"를 뺐습니다. 데이터베이스의 옛 표와 함수는 삭제하지 않았습니다.
v2.1.0 내용메뉴 이름(운행습관 리포트, 피드백 대화창), 큰 글씨 기사 화면, 열면 자동 확인, 관리자 "전체 연결", 파일명 자동 매칭이 모두 들어 있습니다.

적용 순서

  1. 백업: 현재 사이트 폴더(또는 GitHub 저장소)를 복사해 두고 Netlify Deploys에서 현재 정상 배포를 기록합니다.
  2. SQL 13 (아직 실행하지 않았다면): Supabase SQL Editor에서 sql/13_link_all_and_autoack.sql을 실행합니다. 이미 실행했고 "전체 연결"이 동작했다면 건너뜁니다. 롤백 파일(13_rollback_optional.sql)은 실행하지 마세요.
  3. SQL 14: sql/14_dispatch.sql 내용 전체를 복사해 붙여 넣고 Run. 새 표 2개(dp_days, dp_rows)와 새 함수 dp_api만 추가하며 기존 것은 바꾸지 않습니다. 브라우저 번역 기능이 켜져 있으면 끄고 하세요. 오류가 나면 다음 단계로 넘어가지 말고 전체 오류 문구를 보관합니다.
  4. 파일 반영: 이 ZIP의 safedriver 안 파일을 기존 사이트 루트에 같은 위치로 올립니다. 새 파일은 assets/dispatch.js, assets/pdfviewer.js, netlify/functions/monthly.cjs(수정)입니다. 가능하면 시험 브랜치에 먼저 올립니다.
  5. 배포 확인: Netlify 배포 성공을 확인하고 Ctrl+F5로 새로고침합니다.

배차 올리는 방법 (3~4일마다)

  1. 관리자 로그인 > 배차 관리.
  2. 배차시간표 CSV와 승무원표 XLS를 엑셀에서 열어 저장하지 말고 내려받은 원본 그대로 모두 선택(여러 날짜 가능). 엑셀에서 저장하면 노선 73-1이 날짜(1월-73)로 바뀌고 시각 앞의 0이 사라집니다. 이런 파일은 앱이 오류로 막습니다.
  3. "파일 검사" > 날짜별 결과 표를 확인합니다. 오류가 있는 날짜는 저장할 수 없습니다(차량번호 불일치, 한쪽 파일에만 있는 줄, 같은 사람이 같은 날 두 번 배차, 날짜로 바뀐 노선, 4자리가 아닌 시각).
  4. 경고(빠진 운행순번, 앱에 없는 이름 등)는 저장은 되지만 내용을 확인하세요.
  5. "체크한 날짜 저장". 이미 등록된 날짜는 덮어쓰기 전에 확인을 묻습니다.

시험 확인표 (시험용 기사 계정으로)

  • □ 새 휴대폰(저장 기록 없음)에서 링크를 열면 로그인 창이 나오는가 (URL·키 입력 칸이 없는가)
  • □ 로그인 후 "오늘 근무" 화면에서 본인 근무(오전반/오후반, 노선, 순번, 차량, 시각)가 맞는가 — 배차 원본 파일과 직접 대조
  • □ 휴무인 날에 "휴무", 파일이 없는 날에 "배차 미등록"이 보이는가
  • □ "노선 전체 보기"에서 내 줄이 노란색으로 표시되는가
  • □ 갤럭시, 아이폰, 오래된 기종 각각에서 "리포트 보기"가 앱 안에서 열리는가, 확대/축소·닫기가 되는가
  • □ 앱 안 보기가 실패하는 기기에서 링크 열기로 대체되는가
  • □ 열고 나면 관리자 확인현황에 반영되는가
  • □ 관리자: 실제 CSV·XLS로 업로드 → 날짜별 배차일지와 휴무자 목록이 원본과 맞는가, 같은 날짜 재업로드 시 덮어쓰기 확인이 나오는가

알려진 제한

  • PDF 뷰어는 외부 CDN(jsdelivr)에서 pdf.js 3.11.174를 불러옵니다. 이 환경에서는 그 주소와 실제 휴대폰 동작을 확인하지 못했습니다. 접속이 막히거나 오래된 기기에서 실패하면 자동으로 링크 열기로 바뀝니다. 안정적이면 라이브러리를 사이트에 직접 넣는 방식으로 바꿀 수 있습니다.
  • "오후출발시간 = 오후반 첫 출발"이라는 해석은 파일 이름으로 보아 맞을 가능성이 높지만 같은 날짜의 실제 근무표와 대조해 확인하지 못했습니다. 반드시 시험 계정으로 직접 대조하세요.
  • 두 파일에는 근무 종료 시각, 운휴, 대체기사, 특이사항, 운행 횟수가 없어 표시하지 않습니다. 빠진 운행순번은 운휴인지 누락인지 알 수 없어 업로드 검사 화면에 경고로만 알려 줍니다.
  • 휴무자는 "접속 허용 중인 기사 계정 중 그날 배차에 이름이 없는 사람"입니다. 휴직자·신규 입사자·이름 표기 불일치는 구분하지 않습니다(나중에 처리하기로 한 부분).
  • 기사 이름은 앱의 공단 이름(없으면 계정 이름)과 같을 때만 연결됩니다. 이름이 다르면 그 기사 화면에는 "휴무"로 보일 수 있으니 업로드 검사 화면의 "앱에 없는 이름"을 확인하세요.
  • Supabase 무료 한도(전송량)는 12월 3일에 초기화됩니다. 한도 초과 상태에서는 요청이 제한될 수 있습니다.

되돌리기

  1. Netlify Deploys에서 이전 정상 배포로 되돌립니다.
  2. 필요하면 sql/14_rollback_optional.sql로 새 함수만 삭제합니다. 올려 둔 배차 자료(표)는 그대로 남습니다. 표까지 지우는 줄은 파일 안에서 주석을 풀어야 실행됩니다.

검증 범위

실행해 통과한 것: JS 문법 검사, 게이트웨이 시험 3종(배차는 dp_api로만, 새 동작은 mr_api2로만, PDF 바이트 전달의 형식·크기·종류 확인), 배차 병합·검증 시험(날짜로 바뀐 노선, 3자리 시각, 차량 불일치, 한쪽에만 있는 줄, 중복 배차, 이름 정규화, 시각 표기), 모의 화면 시험(오늘 근무 4가지 상태, 업로드 미리보기·덮어쓰기 확인·오류 차단, 앱 안 보기와 대체 열기). 올려 주신 실제 CSV·XLS 1일치(127줄)는 오류 없이 합쳐졌습니다. SQL 11~14는 PostgreSQL 16에 간이 대체 표(app_users 등)를 만들어 실행했고 전체 연결, 파일 연결, 열람 확인, 배차 저장·조회·내 근무·휴무자 동작이 기대대로 나왔습니다. 실제 Supabase 프로젝트의 기존 정의가 다를 수 있습니다.
실행하지 못한 것: 실제 Supabase·Netlify, 실제 휴대폰과 브라우저에서의 화면, pdf.js의 실제 표시.
