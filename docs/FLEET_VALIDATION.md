## 테스트 구성 및 한계

- Python 단위 테스트 6개, JavaScript 파서 체크 6개를 포함했습니다.
- `tests/test_db.mjs`는 PGlite 패키지와 원본 SQL을 별도 검증 작업폴더에서 사용합니다. 운영 프로그램 의존성이 아닙니다. 경로 형식은 실행 오류 안내에 명시되어 있습니다.
- 로컬 DB 테스트의 기존 로그인용 pgcrypto 함수는 테스트 대역으로 대체했습니다. 이번 변경은 비밀번호/로그인 로직을 수정하지 않으며, 운영 Supabase 인증 자체를 검증했다는 뜻은 아닙니다.
- 웹 테스트는 실제 운영 Supabase 대신 가상 API를 사용했습니다. SQL 함수 동작은 별도 로컬 DB에서 검사했습니다.
- 테스트 환경에 한글 글꼴이 없어 화면 캡처의 한글은 대체 기호로 보였습니다. DOM의 한글 텍스트와 업로드 결과는 정상 확인했습니다. 운영 PC의 실제 글꼴/레이아웃은 적용 후 확인 대상입니다.
- 회사 Windows PC의 수집기 자동실행, 운영 TAGO 응답, 운영 Supabase 정책/함수의 첨부 소스와의 일치 여부, Netlify 배포는 확인하지 않았습니다.
- 기존 잘못된 연결에서 파생된 과거 기사 집계나 발행 자료는 자동 정정하지 않습니다. 이번 변경은 명부 기반 조회 및 이후 수집 제한입니다.
- 자사 차량 사이의 교체 판단 알고리즘 자체는 기존 방식입니다. 명부 필터가 실제 운전자/순번의 정확성을 보증하는 것은 아닙니다.
