# SafeDrive AI v1.4.1 변경사항

## 핵심 수정

1. **일일배차 CSV 인식 오류 수정**
   - 실제 첨부 CSV의 헤더 `운행순번`을 정식 인식하도록 보완.
   - UTF-8 / CP949(EUC-KR) CSV 자동 판별.
   - `.xls`, `.xlsx`, `.csv`를 개별 또는 여러 파일 동시 업로드 가능.
   - 기사 근무배차와 일일 노선·운행순위 파일을 업로드 순서와 관계없이 `운행일+차량+AM/PM`으로 병합.

2. **시간표 운용 단순화**
   - 노선별 시간표 Excel은 한 번 등록하면 다음 시간표 업로드 전까지 계속 적용.
   - 새 시간표 업로드 시 기존 시간표의 적용 종료일을 자동으로 이전 날짜까지 정리.
   - 별도 공휴일/특수일 수기 입력 UI 제거.
   - 일일배차의 노선·순번·예정출발을 BIS 실시간 비교의 우선 기준으로 사용.

3. **BIS 실제차량 판정 강화**
   - 배차 예정차량과 TAGO/BIS 실제 운행차량의 불일치를 반복 확인 후 `출발대체` 또는 `운행중교체`로 저장.
   - 관리자 메뉴를 `실제 운행차량·차량변경` 중심으로 표현.
   - CDT는 차량변경 원인을 판단하지 않고, 확정된 실제차량을 기사 운행분석에 연결하는 용도로만 사용.

4. **CDT 0건 진단 및 수집 강화**
   - 지정 폴더 바로 아래뿐 아니라 **모든 하위폴더의 `.CDT`를 재귀검색**.
   - Collector 처리상태에는 완료인데 Supabase에 해당 원본 파일 이력이 없는 경우 자동 재처리.
   - 수집현황에 `폴더 내 CDT / DB확인 / 신규·재처리 후보 / 이번 실행 처리 / 매칭대기`를 분리 표시.
   - 차량 입고·수리로 하루 또는 며칠 늦게 생성된 CDT는 파일의 실제 운행일 기준으로 과거 배차·BIS 이력과 재매칭.

5. **기사 분석 차량매칭 우선순위 수정**
   - BIS로 확정된 실제차량 연결정보를 예정 배차차량보다 우선 적용.
   - 출발대체 또는 운행중교체 차량의 CDT가 해당 기사 분석에 포함됨.

## 데이터 보존 원칙

- 기존 Supabase 데이터 삭제 없음.
- 기존 GitHub 저장소와 Netlify Site 유지.
- 운영 중인 `config.js`는 교체하지 않음.
- `collector_config.json`, `collector_state.json`은 백업 후 그대로 복원.
- Supabase 업데이트 SQL은 `CREATE IF NOT EXISTS`, `CREATE OR REPLACE`, `UPSERT`, 기존행 보완 방식만 사용.
