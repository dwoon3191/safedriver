## 2. 코드 정적검증
- `assets/app.js`: `node --check` 통과
- `collector/daewoon_collector.py`: `python -m py_compile` 통과
- Supabase SQL: 테이블/RLS/RPC/권한 선언을 정적 점검함
- SECURITY DEFINER 함수는 기본 PUBLIC 실행권한을 제거하고 외부 사용 RPC만 anon/authenticated에 명시적으로 허용

> 이 환경에는 실제 Supabase PostgreSQL 인스턴스가 연결되어 있지 않아 `sql/01_schema.sql`의 실DB 실행시험은 수행하지 못했음. 설치 시 Supabase SQL Editor에서 전체 실행 후 로그인/업로드 인수시험 필요.

## 4. BIS 차량교체 로직 시험
합성 시나리오에서 다음 조건을 시험함.
- 노선 106 예정차량: 경남71자1352 / 기사 명상식 / 운행순위 1
- 직전 위치: 정류소 순서 10
- 새로 관측된 차량: 경남71자9999 / 정류소 순서 11
- 1회 관측: 저장하지 않음
- 동일 변화 2회 연속 관측: 차량교체 후보 확정
- 결과: 경남71자1352 → 경남71자9999, 신뢰도 high
- Supabase에는 전체 실시간 위치가 아니라 변경 이벤트만 저장하도록 설계

오전/오후 승무원이 섞이지 않도록 근무 시작/종료시각이 있으면 현재 시각에 실제 근무 중인 행만 BIS 비교 대상으로 사용하고, 시각이 없을 때만 AM/PM을 보조 기준으로 사용한다.

## 5. 기사 분석 공개/확인 정책
- 배차 또는 eTAS 업로드 시 기사 이름으로 계정 자동 생성
- 초기 비밀번호 1111, 첫 로그인 후 1111 재사용 불가
- 기사는 본인에게 연결된 자료만 RPC를 통해 조회
- 기사별 분석자료에 `확인했습니다` 기능 제공
- 관리자는 기사별 공개일/확인여부/확인시각 확인 가능
- 분석자료가 재산출·갱신되면 기존 확인을 해제하여 새 결과를 다시 확인하도록 설계

## 6. 현장 인수시험이 필요한 항목
1. Supabase 프로젝트에 SQL 전체 실행
2. 관리자 최초 로그인 및 비밀번호 변경
3. 첨부 배차표 2종 동시 업로드 → 254명/근무 배차의 병합 확인
4. eTAS 샘플 업로드 → 강명구B 리포트 표시 확인
5. 기사 모바일 로그인 → 본인자료 및 확인버튼 시험
6. 회사 PC `E:\Choyoung\ADTviewer\Data` 실제 CDT 생성 감시
7. TAGO 서비스키로 창원시 실제 노선 위치 조회
8. 실제 차량교체 1건 발생 시 회사 BIS 화면과 TAGO 탐지결과 대조
9. 동일 이름 기사가 존재하는지 인사자료 확인 (동명이인일 경우 회사 규칙에 따라 이름에 식별자를 추가해야 함)
10. Netlify 운영 URL에서 PC/Android/iPhone 화면 및 권한별 접근 시험
