먼저 확인하세요

이 파일은 v1.4.x 기존 프로그램에 덮어쓰는 v2.0.0-rc1 업데이트입니다.

신규 설치용 전체 프로그램이 아닙니다. 기존 config.js, app.css와 데이터베이스가 필요합니다. 운영 사이트에는 아직 반영되지 않았습니다.

공단 자동 다운로드는 실제 로그인 환경에서 검증되지 않았습니다. 화면 연결 도우미와 소량 시험이 필요하며, 사이트 구조에 따라 추가 수정이 필요할 수 있습니다. 수동 다운로드 → 일괄 등록 경로는 함께 제공합니다.

PDF·엑셀 원본 보관, 기사별 월간 열람, 확인 기록, 피드백, 계정 관리가 이번 범위입니다. 문자 발송은 제외했습니다. 분기·반기·연간 수치 계산 화면은 이번 버전에 포함되지 않습니다. 엑셀을 보관한 뒤 실제 지표·계산 기준을 검토하여 추가해야 합니다.

권장 순서: 백업 → SQL 추가 → 비공개 파일 저장소 → Netlify 환경변수 → 파일 배포 → 소수 기사 시험 → 기존 수집기 중단.

1. 준비물과 파일 구분

준비물확인
기존 GitHub 저장소index.html, assets, config.js가 있는 실제 배포 폴더를 확인합니다.
Supabase 관리자 접속현재 프로그램이 쓰는 프로젝트인지 확인합니다.
Netlify 관리자 접속dwoondriver.netlify.app에 연결된 프로젝트를 확인합니다.
Windows PC공단 사이트 로그인 가능, G: 접근 가능, Python 3 설치 가능해야 합니다.
시험 자료기사 1~2명의 같은 분석월 PDF와 엑셀, 시험용 기사 계정을 준비합니다.

ZIP을 마우스 오른쪽 버튼으로 눌러 모두 압축 풀기를 선택합니다. 안의 safedriver 폴더가 업데이트 파일입니다. ZIP 상태에서 프로그램을 실행하지 마세요.

바뀌는 기존 파일: index.html, assets/app.js, netlify.toml, VERSION.txt. 새 파일: assets/monthly.js, netlify/functions/monthly.cjs, SQL 11·12, collector/monthly_* 및 공단수집기 배치 파일. assets/fleet.js는 기존 명부 모듈입니다.

2. 기존 프로그램 백업

  1. 현재 PC 프로그램 폴더를 통째로 복사해 safedriver_변경전_20261108처럼 별도 보관합니다.
  2. GitHub에서 기존 저장소를 열고 Code → Download ZIP으로 현재 코드를 내려받습니다. 운영 PC의 config.js도 별도 보관합니다.
  3. Netlify의 Deploys 화면에서 현재 정상 배포 항목과 날짜를 기록합니다. 문제 발생 시 돌아갈 배포입니다.
  4. Supabase의 백업 기능 이용 가능 여부를 확인하고, 가능하면 변경 전 백업을 확보합니다. 기능은 이용 요금제에 따라 다를 수 있습니다. 계정·배차 등 중요한 표의 내보내기도 보관하되, CSV 내보내기가 전체 DB 백업을 대신하지는 않습니다.

이번 SQL은 기존 보고서·배차·BIS·CDT 테이블을 삭제하지 않습니다. 기본 계정 구조를 재사용하며 새 테이블 3개를 추가합니다.

3. Supabase에 SQL 11 실행

  1. Supabase에서 현재 운영 프로젝트를 선택합니다.
  2. 왼쪽의 SQL Editor를 열고 새 쿼리를 만듭니다.
  3. 업데이트 폴더의 sql/11_monthly_reports.sql을 메모장으로 엽니다.
  4. Ctrl+A → Ctrl+C로 전체 복사한 뒤 SQL Editor에 붙여넣습니다.
  5. Run을 눌러 실행합니다.
  6. 오류 없이 끝났는지 확인합니다. 오류가 나면 뒤 단계로 넘어가지 말고 전체 오류 문구를 보관합니다.
기존 sql/01_schema.sql을 다시 실행하는 절차가 아닙니다. 이번에는 11_monthly_reports.sql만 실행합니다. 기존 v1.4.x 프로젝트가 전제입니다.

추가되는 표: mr_profiles(공단 이름·재직상태), mr_reports(월간 자료·확인), mr_messages(피드백·내부 메모). 이름이 같은 표를 다른 용도로 직접 만든 적이 있다면 먼저 검토가 필요합니다.

4. Supabase에 SQL 12 실행

  1. 새 SQL 쿼리를 하나 더 엽니다.
  2. sql/12_private_storage.sql 내용을 전체 복사해 실행합니다.
  3. Storage 메뉴에서 driver-monthly-private 저장소가 만들어졌는지 확인합니다.
  4. Public이 꺼진 비공개 상태인지 확인합니다. 공개 전환이나 모든 사용자 허용 정책을 추가하지 마세요.

PDF와 엑셀을 웹에도 등록합니다. 기사는 PDF만 열 수 있고, 엑셀은 관리자용입니다. G:에는 원본이 별도로 남습니다. 파일당 최대 3MB입니다. 초과 자료는 이 버전에서 웹 등록할 수 없으므로 별도 대응이 필요합니다.

5. Netlify에 서버 환경변수 등록

새 기능은 서버에서 기사 권한을 확인하고 비공개 파일을 연결합니다. 이를 위해 Netlify Functions용 환경변수 두 개를 등록해야 합니다.

변수 이름 — 그대로 입력값
SUPABASE_URL현재 Supabase 프로젝트 URL. 기존 config.js의 url과 같은 프로젝트입니다.
SUPABASE_SERVICE_ROLE_KEYSupabase 프로젝트의 서버 전용 service_role 키. 기존 브라우저용 anon 키와 다릅니다.
  1. Supabase 프로젝트 설정의 API Keys에서 해당 프로젝트의 service_role 키를 확인합니다. 화면 구성에 따라 Legacy API keys 항목에 있을 수 있습니다.
  2. Netlify → 해당 프로젝트 → Project configuration → Environment variables에서 Add variable을 선택합니다. 메뉴 이름은 서비스 화면 개편에 따라 다를 수 있습니다.
  3. 위 두 변수를 각각 등록합니다. Functions 범위 또는 해당 범위를 포함하는 설정으로 등록합니다.
  4. 운영 Production에 적용하고, 별도 시험 배포를 사용한다면 필요한 시험 환경에도 설정합니다.
  5. 키를 바꾼 후에는 새 배포가 필요합니다.
service_role 키는 config.js, GitHub 파일, 브라우저 입력창, 이 대화에 붙여넣지 마세요. Netlify의 서버 환경변수에만 저장합니다. 기존 config.js의 anon/publishable 키는 그대로 유지합니다.

6. GitHub에 업데이트 파일 반영

  1. GitHub 저장소에서 실제 사이트 파일이 있는 폴더로 이동합니다. index.html이 보이는 위치입니다.
  2. 가능하면 새 작업 브랜치 monthly-reports-v2를 만들어 먼저 시험합니다. 운영 브랜치에 직접 올리면 연결된 Netlify에서 즉시 배포될 수 있습니다.
  3. Add file → Upload files를 누릅니다.
  4. 압축 푼 safedriver 폴더 안의 파일과 폴더를 같은 위치에 올립니다. 기존 index.html 옆에 safedriver 폴더를 한 겹 더 만드는 방식이 아닙니다.
  5. 변경 목록에서 index.html, assets/app.js, assets/monthly.js, netlify/functions/monthly.cjs, netlify.toml이 올바른 위치인지 확인합니다.
  6. Commit changes로 저장합니다. 브랜치로 작업했다면 검토 후 운영 브랜치로 병합합니다.

이번 ZIP에는 운영 config.js가 없습니다. 기존 파일을 지우거나 대체하지 마세요. 기존 app.css와 이미지도 그대로 유지합니다. 별도 사용자 설정을 추가한 netlify.toml이라면 통째로 덮어쓰기 전에 비교하고 기존 설정과 병합해야 합니다.

PC 수집기만 사용하는 로컬 설정 파일(collector_config.json), 로그인 자료, G:의 보고서, .venv_monthly, 브라우저 프로필은 GitHub에 올리지 않습니다. 이번 패키지에는 이런 운영값이 들어있지 않습니다.

7. Netlify 배포 확인

  1. Netlify → Deploys에서 방금 GitHub 변경을 반영한 배포가 성공했는지 확인합니다.
  2. Functions 목록에서 monthly 함수가 생성됐는지 확인합니다.
  3. 기존 사이트를 열고 Ctrl+F5로 새로고침합니다.
  4. 기존 관리자 ID로 로그인합니다. 새로 계정을 만들 필요는 없습니다.
  5. 월별 종합진단표 / 수집·등록 / 기사 계정 / 피드백·지도 메뉴가 보이는지 확인합니다.

단순 정적 파일 드래그 배포만으로는 서버 함수가 준비되지 않을 수 있습니다. GitHub 연동 빌드를 사용하고 Functions 생성 여부를 확인하세요. 새 SQL과 서버 환경변수가 빠져 있으면 월간 화면에 오류가 표시됩니다.

8. 기사 계정과 공단 이름 연결

  1. 웹앱에서 기사 계정을 엽니다.
  2. 기존 기사 옆 정보·연결 수정을 누릅니다.
  3. 공단 화면의 기사 이름을 B 등의 표식까지 그대로 입력합니다.
  4. 재직 / 휴직 / 퇴사, 적용일, 접속 허용 여부를 지정하고 저장합니다.
  5. 신규 입사자는 신규 기사 등록에서 ID와 6자 이상 초기 비밀번호를 지정합니다. 기사는 첫 로그인 때 비밀번호를 변경해야 합니다.

계정 삭제(접속중단)는 즉시 로그인과 기존 세션을 막고, 과거 보고서·피드백은 보존합니다. 재입사 시 정보·연결 수정에서 접속을 다시 허용할 수 있습니다. 물리적 개인정보 영구삭제 기능은 아닙니다.

퇴사·휴직은 현재 상태입니다. 과거 재직 월의 수집 필요 여부는 관리자가 판단합니다. 현재 퇴사했다고 모든 과거 보고서를 자동 제외하지 않습니다.

9. 먼저 수동 자료로 웹 기능 시험

  1. 공단에서 시험 기사 1명의 PDF와 엑셀을 내려받습니다. 상세 종합진단표를 사용합니다. 배치인쇄의 간단 진단표와 구분하세요.
  2. 파일명을 홍길동B(2026-07).pdf, 홍길동B(2026-07).xlsx 형태로 맞춥니다. 실제 XLS 파일이면 확장자는 .xls 그대로 둡니다.
  3. 웹앱의 수집·등록에서 두 파일을 선택하고 선택 파일 검사·계정 연결을 누릅니다.
  4. 기사 계정과 분석월을 확인합니다. 이름이 연결되지 않으면 목록에서 직접 선택합니다.
  5. 체크한 정상 파일 웹 등록을 누릅니다. 실패한 항목은 사유를 확인하고 다시 체크해 재시도합니다.
  6. 월별 종합진단표로 이동합니다. PDF와 엑셀을 각각 열어 원본의 기사명·분석월을 확인합니다.
  7. 해당 행을 체크하고 선택 자료 내용·계정 검증 완료를 누릅니다.
  8. 다시 해당 행을 체크하고 선택 자료 게시를 누릅니다.
  9. 시험 기사의 휴대폰/별도 브라우저에서 로그인하고 본인 PDF가 보이는지 확인합니다.
  10. PDF를 연 뒤 확인 완료를 누릅니다. 관리자 확인현황에 기록되는지 확인합니다.

웹 검사에서는 파일명, 형식의 시작 바이트, 용량을 확인합니다. PDF·엑셀 내부 내용을 자동으로 완전히 검증하는 기능은 아닙니다. 관리자의 내용 대조가 반드시 필요합니다.

열람 기록은 PDF 링크를 여는 요청 시점입니다. 모든 페이지를 읽었거나 내용을 이해했다는 의미는 아닙니다. 팝업 차단 시 해당 사이트의 팝업을 허용하세요.

10. Windows PC 수집기 설치

  1. 기존 PC 프로그램의 collector 폴더에 이번 collector 파일을 추가합니다.
  2. Python 3가 없으면 공식 Python Windows 다운로드에서 설치합니다. Python 3.11 이상 환경을 권장하며, 설치 시 Python Launcher를 포함합니다.
  3. 공단수집기_설치.bat을 더블클릭합니다. 필요한 라이브러리와 전용 Chromium 브라우저가 설치됩니다.
  4. 설치 완료 문구를 확인합니다. 실패하면 창을 닫기 전 오류 내용을 보관합니다.
  5. 공단수집기_실행.bat을 더블클릭합니다.

작업 목록과 설정은 %LOCALAPPDATA%\DaewoonMonthly에 저장됩니다. PC에서 Windows+R을 누르고 이 경로를 입력하면 열 수 있습니다. 이 폴더를 삭제하면 재개 정보가 사라집니다. 브라우저 로그인 정보가 포함될 수 있으므로 다른 사람에게 전달하지 마세요.

기존 Whale 창에 자동 연결하는 방식이 아닙니다. 수집기가 여는 전용 브라우저에서 직접 로그인합니다. 공단 ID·비밀번호를 프로그램 설정 파일에 입력하지 않습니다.

11. 기간과 G: 저장 폴더 지정

  1. 웹앱 수집·등록 메뉴의 수집용 기사명부 내보내기로 기사명부.json을 저장합니다.
  2. PC 수집기에서 기사명부 불러오기를 눌러 해당 파일을 선택합니다.
  3. 시작월·종료월을 YYYY-MM 형식으로 입력합니다. 처음에는 같은 월 한 개로 시험합니다.
  4. 기간별 작업 생성을 누릅니다. 기사 × 월 × PDF·엑셀로 작업이 만들어집니다.
  5. 저장 루트 선택을 누르고 G:\내 드라이브\승무원 내부평가\기사별 운행보고서에 해당하는 실제 폴더를 선택합니다. 경로 표시는 PC 환경에 따라 달라질 수 있습니다.

12. 공단 화면 연결과 소량 자동 수집 시험

실제 공단 화면에서 아직 검증되지 않은 단계입니다. 화면 구조·보안 프로그램·다운로드 방식이 다르면 추가 수정이 필요합니다. 성공한 것처럼 전체 수집을 진행하지 않고 오류 시 멈추도록 만들었습니다.
  1. 공단 사이트 열기를 누릅니다. 열린 전용 브라우저에서 로그인하고 종합진단표 메뉴로 이동합니다.
  2. 시험 월의 기사 1명을 직접 열어 파일다운로드 → 보고서 뷰어까지 이동합니다.
  3. PC 수집기의 첫 연결 도움에서 ‘보고서 저장 아이콘’을 선택하고 ‘화면에서 해당 요소 지정’을 누릅니다.
  4. 60초 안에 공단 브라우저에서 실제 저장 아이콘을 한 번 클릭합니다. 이 클릭은 위치를 저장하기 위한 것이며 실제 저장 메뉴를 열지는 않습니다.
  5. 저장 아이콘을 다시 클릭하여 저장 설정 창을 엽니다.
  6. 같은 방법으로 ‘파일 형식 선택’, ‘파일명 입력칸’, ‘전체 페이지’, ‘최종 저장 버튼’을 각각 지정합니다.
  7. 필요하면 종합진단표 화면의 조회 연도·월·조회 버튼, 기사 상세창의 파일다운로드도 같은 방식으로 지정합니다.
  8. 직접 연 보고서 팝업/탭을 닫고 회사별/개인별 목록이 있는 종합진단표 화면으로 돌아갑니다.
  9. PC 목록에서 기사 1명의 PDF·엑셀 두 행을 선택하고 선택 작업 수집/재수집을 누릅니다.
  10. 재직 상태와 작업 수를 확인하고 진행합니다. 수집 중에는 해당 브라우저를 다른 용도로 조작하지 않습니다.
  11. 두 작업이 완료되면 G:의 파일을 직접 열어 기사명·분석월·페이지·내용이 맞는지 확인합니다.

연결 설정은 자동 저장됩니다. 기존 명부 기준으로 필요한 기사를 찾으며 여러 페이지를 탐색합니다. 페이지 그룹 이동이 필요한 구조나 확인할 수 없는 요소는 관리자 확인 대상으로 멈출 수 있습니다. 연결을 다시 지정해도 실패하면 오류 문구와 해당 화면을 전달해 추가 수정해야 합니다.

사이트의 ‘약 5분 분석’ 안내처럼 응답이 늦을 수 있습니다. 현재 한 파일 다운로드 대기는 최대 180초이며, 초과 시 실패로 남습니다. 충분히 로딩된 뒤 실패 항목만 재시도하세요.

13. 실패·중단·자료 없음 처리

버튼 / 상태사용법
일시중지현재 처리 중인 파일 작업이 끝나거나 실패한 뒤 다음 항목부터 멈춥니다.
미완료 대기 건 선택현재 기간의 대기·진행 중 항목을 선택합니다. 재직 상태를 보고 수집을 시작하세요.
실패·확인필요 건 선택문제 항목만 선택합니다. 다시 받을 것만 Ctrl/Shift로 선택 조정하세요.
보류 / 이번 수집 제외관리자가 사유를 입력합니다. 이후 자동 재선택 대상에서 빠집니다.
공단 자료 없음 확인공단 화면을 직접 확인했을 때만 사용합니다. 링크를 찾지 못했다는 오류와 다릅니다.
대기로 되돌리기보류·제외·자료 없음 판단을 변경해 다시 수집할 때 사용합니다.
결과 CSV 내보내기전체 이력을 내보냅니다. 엑셀에서 상태 열을 필터링해 확인 필요 목록으로 사용합니다.

PDF만 성공하면 엑셀 항목만 선택해 재시도합니다. 완료 파일은 자동 재다운로드하지 않습니다. 같은 경로에 내용이 다른 파일이 있으면 덮어쓰지 않고 멈춥니다. 기존 파일을 별도로 보관하고 이름 오류 여부를 확인한 후 처리하세요.

수동 다운로드 파일 연결은 목록의 작업 한 개를 선택하고 해당 PDF/XLS/XLSX를 지정하는 기능입니다. 파일 내용에서 기사명·분석월을 추출하지 못하면 확인 필요로 남깁니다. 정상 원본인데 텍스트 추출이 어려우면 웹의 수동 등록과 관리자 대조 절차를 사용하세요.

14. 매월 실제 운영 순서

  1. 입사·퇴사·휴직 변동을 기사 계정에 반영합니다.
  2. 새 명부를 내보내 PC 수집기에 불러옵니다.
  3. 분석기간과 G: 저장 루트를 확인하고 작업을 생성합니다.
  4. 공단에 로그인하고 선택 작업을 수집합니다.
  5. 확인 필요 목록에서 재수집·보류·제외·자료 없음을 구분합니다.
  6. 웹앱 수집·등록에서 해당 월의 PDF·엑셀을 선택해 등록합니다. 두 폴더의 파일을 나누어 등록해도 같은 기사·월로 연결됩니다.
  7. 월별 보고서에서 내용을 검증하고 선택 게시합니다.
  8. 기사들은 로그인해 원하는 월의 PDF를 열고 확인 완료를 누릅니다.
  9. 관리자는 확인현황과 피드백·지도 이력을 관리합니다.

문자 발송 버튼과 자동 안내는 없습니다. 새 자료 등록 사실은 기존 회사 안내 방식으로 전달하세요.

15. 피드백과 잘못 등록한 자료 정정

피드백·지도에서 기사를 선택하고 관련 진단표 또는 일반 대화를 지정합니다. 관리자는 피드백·민원·사고·지도 분류를 선택할 수 있습니다. 관리자 내부 메모를 체크하면 기사 화면에서는 보이지 않습니다. 기사 메시지는 본인 대화에만 저장됩니다.

파일명을 잘못 지었다면 로컬 파일명을 고친 뒤 다시 검사합니다. 웹에 다른 기사의 자료를 올렸다면 먼저 해당 자료의 게시를 취소하고 올바른 기사에 등록합니다. 잘못된 기존 행은 게시하지 않은 상태로 두고 올바른 파일로 교체합니다.

동일 내용 파일을 다시 올리면 중복 등록하지 않습니다. 내용이 다른 파일로 교체되면 검증·게시·열람·확인 기록이 초기화되어 다시 검증·게시해야 합니다. 이전 파일 경로와 변경 이력은 작업이력에 남습니다. 이전 원본은 자동 삭제하지 않습니다.

16. 전환 완료 후 기존 BIS/CDT 수집 중단

  1. 새 월별 보고서가 기사 휴대폰에서 열리고 확인 기록도 남는지 먼저 시험합니다.
  2. 기존 PC 수집 제어센터에서 수집 중지를 누릅니다.
  3. 기존 collector/remove_autostart_task.bat 또는 제어센터의 자동실행 해제 기능을 사용합니다. 기존 파일과 화면에 따라 절차가 다를 수 있습니다.
  4. PC를 다시 시작한 뒤 기존 BIS/CDT 수집기가 자동으로 켜지지 않는지 확인합니다.

웹 파일 교체만으로 이미 실행 중인 PC 수집기가 멈추지는 않습니다. 기존 데이터는 남겨 두세요. 배차표·시간표 메뉴는 업무 활용 여부가 확정되지 않아 유지했고, 새 월간 보고서 분석에는 사용하지 않습니다.

18. 운영 전 최종 확인표

  • 기존 관리자 로그인과 비밀번호 변경이 된다.
  • 공단 기사명 B 표식을 포함해 연결했다.
  • 기사 A 계정으로 기사 B의 PDF가 보이지 않는다.
  • 비공개 자료는 기사에게 보이지 않는다.
  • PDF·엑셀이 모두 있어야 검증·게시가 된다.
  • 휴대폰에서 PDF가 열리고 확인 완료가 기록된다.
  • 내부 메모는 기사에게 보이지 않는다.
  • 계정 접속 중단 후 기존 로그인 세션도 사용할 수 없다.
  • 다운로드 중단 후 대기 건부터 재개된다.
  • G: 원본의 기사명·월·내용·페이지가 맞다.
  • 실패·자료 없음·보류·제외가 성공과 구분된다.
  • 운영 전환 후 기존 수집 자동실행을 해제했다.

실제 공단 다운로드, 운영 Supabase Storage, Netlify 배포, Windows G: 동작은 사용자 환경에서 위 절차로 확인해야 합니다. 로컬 테스트 통과가 이 항목들의 운영 검증을 대신하지 않습니다.
